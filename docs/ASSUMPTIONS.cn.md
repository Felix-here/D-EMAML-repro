# 复现假设与已知缺口

## 论文可以直接确认的内容

- AMLWorld 表中约有 518,573 个账户、5,078,345 笔交易，异常交易大约 0.15%。
- 边按时间顺序切成 60% / 10% / 30%。
- 双边基序是共享至少一个端点的有序交易对。
- 基序标签为 `Y = y1 + 2*y2`。
- motif 图把共享同一笔原交易的基序连起来。
- AMLWorld 使用 `xi=0`、`eta=6`；结构是两层、隐层 256、两跳邻居最多各 100、最多 50 个 epoch。
- 主指标是 AUPRC，报告五次独立运行。
- 图 3 的六种结构：`b1` 重复转账、`b2` 互转、`t1` 扇入、`t2` 反向时间链、`t3` 前向链、`t4` 扇出。

## 实现时不得不做的假设

1. **时间单位。** 图 3 把间隔 1、3、5 小时画成 δ=0、1、2。因此采用
   `delta=floor(log2(max(1, ceil((t2-t1)/3600))))`。
2. **六类编号。** 先判 `b1`、`b2`，其余再按三元条件：`t1` 相同收款方，`t2` 第一笔付款方等于第二笔收款方，`t3` 第一笔收款方等于第二笔付款方，`t4` 相同付款方。
3. **自环。** 付款方与收款方相同的交易不参与基序枚举。
4. **时间相同。** 定义 2 允许 `t1 <= t2`，算法 1 要求 `t2 > t1`。并列时按原始行号稳定排序。
5. **划分隔离。** 只让同一时间划分里的两笔交易组成基序，避免把未来标签漏进训练集。
6. **度数裁剪。** 论文没给 AMLWorld 的 `dmax`。账户交易过多时，按均匀间隔保留，默认 `dmax=256`。
7. **特征。** 作者 README 写了 `input_dims=1048`，但公开材料没有定义这 1048 维。这里把两笔交易编码、缩放后的 δ、以及六类 one-hot 拼在一起，并在日志里记下真实维数。
8. **小批量损失。** 公式 (16) 要先对包含某条边的所有基序预测取平均再做 BCE。邻居采样小批量做不到全局聚合。训练时用种子基序上的边出现边际损失；验证/测试再对全部种子基序精确聚合。
9. **motif 图裁剪。** 论文没说一笔交易最多对应多少个基序。全量基序约 30 GiB 时，128 个邻居会展开出超出实例内存的团，因此默认改为 8。
10. **未被覆盖的边。** 从未进入保留基序的交易不计入 F1/AUPRC，只报告覆盖率，不另做补救分类器。
11. **原图 GAT。** `gate` 是对照用的重实现，不是 IBM Multi-GNN 的 GATe。划分与主实验相同。

## 故意没有照抄的公开代码问题

- 源列里 `Amount Received` 出现了两次。
- 支付方式的独热列是用货币值生成的。
- `process_data.py` 处理完 AMLWorld 还会去跑 DGraph。
- 公式 (13) 把 softmax 写成 `0..2^|E|-1`；模型实际只有四个基序类别，这里用四个 logit。
- Fast-Motif-Gen 的稠密 `AdjInd` 是 `O(|E|^2)`，这里不会物化。

本项目的结果是独立重实现，不能当成对作者未公开实现的核验。
